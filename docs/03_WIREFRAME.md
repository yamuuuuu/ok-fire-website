## 9. 핵심 UX 원칙
- 고객 CTA는 전화와 접수 2개에 집중
- 전문용어만 사용하지 않음
- 모바일 관리자에서 전화번호와 주소를 액션으로 취급
- 신규접수는 강조
- 접수 상세를 봤다고 자동 상태변경하지 않음

## 10. Phase 2 접수 UX 구현
- 각 단계에 진행 표시, 필드별 오류, 최소 52px 입력 영역과 하단 고정 이전/다음/접수 버튼.
- 이전 버튼으로 이동해도 입력값 유지. 잘못된 필드와 단계 제목으로 키보드 포커스 이동.
- STEP 3에 선택 공사 희망일과 사진 선택/삭제/미리보기를 제공합니다. 저장소 미설정 시에만 사진 준비 안내를 표시합니다.

## 11. Phase 3 사진 UX
- 파일당 10MB, 최대 10장을 선택할 수 있습니다. 초과 선택/잘못된 형식은 선택 단계에서 안내합니다.
- 사진은 동의 전 서버에 전송하지 않습니다. STEP 5에서 사진과 입력 내용을 함께 확인합니다.
- 업로드 중 사진 순번과 전송/확인 상태를 표시하고 중복 제출을 막습니다.
- 접수가 이미 생성된 후 사진 전송 실패 시 입력을 잠급니다. 사진만 재시도하거나 저장된 사진으로 완료할 수 있습니다.
- 새로고침 시 파일과 고객 입력은 복원하지 않습니다. 고객 사진을 브라우저 영구 저장소에 남기지 않습니다.
- STEP 5에 최종 입력 요약과 개인정보 수집·이용 안내를 먼저 표시하고, 기본 해제 상태의 필수 동의 체크박스 제공.
- 접수 실패 시 입력값 유지 및 재시도. 이미 처리된 요청 키로 다른 내용을 보내면 새 접수 시작 안내.
- 완료 페이지는 접수번호만 표시합니다. 고객명/전화번호/주소는 출력하지 않습니다.
- 확인되지 않은 서비스 전화번호는 임의로 표시하지 않습니다. 개인정보 문의 번호와 서비스 대표번호는 별도 취급합니다.

## 12. Phase 4 관리자 접수 UX

- 접수 목록은 모바일에서 카드, PC에서 표로 전환합니다. 검색·필터는 같은 URL query로 동작하고 모바일 입력과 버튼은 최소 44px 높이를 유지합니다.
- 카드에는 상태/접수번호, 고객명, 누르면 전화되는 연락처, 주소, 문의유형, 사진 수, 담당자, 접수일을 표시합니다.
- 상세 모바일 화면은 고객정보 → 현장주소 → 문의내용 → 고객사진 순으로 배치하고, 전화·지도 액션을 관리자 하단 메뉴 위에 고정합니다.
- PC 상세는 좌측 고객/현장/문의/사진/메모, 우측 상태/방문/견적/이력/접수정보의 2열입니다.
- Phase 5 전까지 상태와 담당자는 읽기 전용입니다. 준비되지 않은 변경 버튼은 표시하지 않습니다.

## 13. Phase 5 업무 처리 UX

- 상세의 고객사진 아래에 상태 변경과 담당자 지정, 상담메모를 배치합니다. 상태 변경 메모는 선택이며 저장 성공/실패를 바로 안내합니다.
- 모바일 하단은 전화하기와 상태 변경으로 구성합니다. 상태 변경은 업무 처리 영역으로 스크롤해 키보드와 터치로 조작할 수 있습니다.
- 메모 카드에는 작성자·시각·수정·삭제를 표시합니다. 작성자나 최고 관리자에게만 수정/삭제 버튼을 노출합니다.
- 상태/담당자 변경 이력은 접수 이력에서 시간순으로 확인합니다.

## 14. Phase 7 고객 공개 웹 UX

- 공통 헤더는 회사소개, 서비스, 작업사례, FAQ와 상담 접수로 구성하며 모바일에서는 메뉴 버튼으로 펼칩니다.
- 홈은 30년 현장 경험, 서비스, 문의 상황, 상담 절차, 상담 CTA 순으로 구성합니다.
- 모바일 하단은 전화 상담 안내와 간편 상담 접수 CTA를 고정합니다. 대표 전화번호 확정 전 전화 영역은 연결하지 않습니다.
- 작업사례와 FAQ는 공개 CMS 데이터가 없을 때 준비 안내를 표시합니다.

## 15. Phase 8 CMS UX

- 관리자 사이드바와 모바일 메뉴에서 작업사례·FAQ로 이동합니다.
- 작업사례 편집 화면은 제목, 공개 주소, 분류, 공개 여부, 지역(상세 주소 제외), 설명과 작업 전/중/후 사진을 관리합니다.
- FAQ는 질문·답변을 등록하고 공개 상태를 즉시 전환합니다.
- 사이트 설정은 유일한 SUPER_ADMIN만 볼 수 있습니다. 별도 관리자 관리 화면은 제공하지 않습니다.
